# Захист інформації

Система обробляє біометричні персональні дані, тому вимоги ТЗ (п. 4.2.1) реалізовано так.

## Вхід до системи і ролі

- Вхід за електронною поштою і паролем (рисунок 4.1), позначка «Запам'ятати мене на 24 години».
- Паролі зберігаються лише як хеші **bcrypt (cost 12)** у `data/users.json`; відкритий пароль ніде не
  записується і не потрапляє в журнали. Пароль – не менше 8 символів, хоча б одна велика літера і одна цифра.
- Після входу сервер видає **JWT (HS256)** зі строком дії **24 години**. Браузер отримує його в cookie
  `HttpOnly; SameSite=Strict` (JavaScript сторінки токен не бачить), клієнти API – у тілі відповіді
  для заголовка `Authorization: Bearer <токен>`. Без «запам'ятати» cookie зникає після закриття браузера.
- Ключ підпису – змінна середовища `PAD_JWT_SECRET` (не менше 32 байт). Без неї ключ генерується
  випадково під час запуску, і після перезапуску всі мають увійти знову.
- **Обмеження спроб:** 5 невдалих спроб за 10 хвилин блокують вхід на 15 хвилин (навіть із правильним
  паролем). Для невідомої адреси перевірка триває так само довго і повертає ту саму помилку, тож
  перебором не можна з'ясувати, які адреси зареєстровано.
- **Вихід** анулює токен до кінця його строку; **блокування** облікового запису адміністратором
  діє одразу (власний обліковий запис адміністратор заблокувати не може) – і на REST, і на відкритий відеопотік WebSocket (з'єднання закривається з кодом 4401).
- Роль і стан користувача беруться з бази під час кожного запиту, а не з токена: зміна ролі не
  потребує повторного входу.

| Дія | Оператор | Адміністратор |
|---|:---:|:---:|
| Дашборд, моніторинг, журнал інцидентів, перегляд сеансів | ✓ | ✓ |
| Сеанс верифікації з активними викликами | ✓ | ✓ |
| Перегляд бази осіб і налаштувань | ✓ | ✓ |
| Додавання і видалення осіб, реєстрація еталона | – | ✓ |
| Зміна порогів | – | ✓ |
| Запис і розмітка набору даних (вкладка «Дослідження») | – | ✓ |
| Облікові записи і журнал аудиту | – | ✓ |

Права перевіряються на сервері для кожного запиту (`pad/server.py`, `admin_only`); інтерфейс лише
ховає недоступні кнопки. У системі завжди лишається хоча б один активний адміністратор.

Перший адміністратор створюється під час першого запуску зі змінних `PAD_ADMIN_EMAIL` і
`PAD_ADMIN_PASSWORD` або командою:

```bash
python scripts/manage_users.py add admin@example.com --role admin
python scripts/manage_users.py list
python scripts/manage_users.py block operator@example.com
```

## Журнали

- **Аудит** (`data/audit.jsonl`, вкладка «Користувачі»): час, користувач, дія і змінені значення для
  додавання і видалення осіб, зміни порогів, керування обліковими записами і розмітки записів.
- **Системний журнал** (`logs/frs-pad.log`): JSON, одна подія на рядок, щодобова ротація, зберігаються
  30 днів; рівень – змінна `LOG_LEVEL` (типово INFO). Входи, виходи, відмови в доступі і блокування
  входу теж потрапляють сюди.
- Кадри відеопотоку в робочому режимі на диск не пишуться; знімки журналу інцидентів – лише в
  пам'яті сервера.

## Транспорт і адреса сервера

- Типово сервер слухає лише `127.0.0.1`; браузер дозволяє вебкамеру на localhost без HTTPS.
- Для доступу з мережі: `--host 0.0.0.0` (або Docker), сертифікат TLS (`PAD_SSL_CERTFILE`,
  `PAD_SSL_KEYFILE`) – тоді інтерфейс працює через **HTTPS і WSS**, а cookie позначається `Secure` –
  і імена сервера в `PAD_ALLOWED_HOSTS`.
- Сервер приймає лише запити з дозволеною адресою в заголовку Host (захист від DNS rebinding).
- POST, PUT, PATCH, DELETE і WebSocket відхиляються, якщо Origin або Sec-Fetch-Site вказують на інший
  сайт: сторінка стороннього сайту в браузері оператора не може нічого змінити чи підключитися до
  відеопотоку.
- Фото – до 10 МБ і лише зображення, кадр WebSocket – до 8 МБ; псевдоніми й ідентифікатори записів
  перевіряються регулярними виразами (вихід за межі каталогу даних неможливий).
- Заголовки `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.

## Біометричні дані

- Еталони осіб, відеозаписи й анотації набору даних – **AES-256-GCM** (ключ `PAD_DATASET_KEY`),
  деталі – [dataset.md](dataset.md#шифрування-записів).
- Учасники набору даних позначаються лише псевдонімами; відеозаписи до репозиторію не входять.
- Ключі й паролі передаються лише через змінні середовища (`.env`, який не додається до Git).

Перевірки – `tests/test_auth.py`, `tests/test_security.py`, `tests/test_logs.py`.
